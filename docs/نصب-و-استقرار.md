# نصب و استقرار نسخهٔ جدید

## اول از همه: پوشهٔ `wordpress/` حذف نشده است

پوشهٔ `wordpress/` **هیچ‌وقت داخل گیت نبوده**. کامیت اولیهٔ مخزن فقط سه فایل داشت:

```
README.md
docker-compose.yml
wordpress.rar
```

آن پوشه روی کامپیوتر خودتان از باز کردن همان آرشیو ساخته شده بود. چون در گیت نبوده،
`git pull` هم آن را پاک نمی‌کند — پوشهٔ `wordpress/` شما سر جایش است.

از این نسخه، آرشیو به‌صورت **`wordpress.zip`** نگهداری می‌شود (به‌جای `wordpress.rar`).
محتوا مو‌به‌مو همان است: هر ۱۰٬۷۴۹ فایل با همان نام و همان اندازه.

## ⚠️ `wordpress.zip` را روی سایت زندهٔ خود اکسترکت نکنید

اگر `parsiancarton.com` همین الان بالا و در حال کار است، **اکسترکت کردن آرشیو کامل
روی `public_html` کار خطرناکی است**:

| خطر | چرا |
|---|---|
| **برگشت نسخهٔ وردپرس و ووکامرس به عقب** | اگر سرور از زمان این بکاپ خودکار به‌روز شده باشد، اکسترکت آن‌ها را قدیمی می‌کند. ووکامرسِ قدیمی روی دیتابیسی که ساختارش به‌روز شده، فروشگاه را می‌شکند |
| **بازنویسی `wp-content/uploads/`** | تصاویری که از آن بکاپ به بعد آپلود شده‌اند سر جایشان می‌مانند، ولی هر فایل هم‌نامی با نسخهٔ قدیمی جایگزین می‌شود |
| **بازنویسی `wp-config.php`** | هر تنظیمی که بعداً روی سرور اضافه کرده‌اید از بین می‌رود |

برای اضافه کردن دو افزونهٔ جدید **نیازی به آرشیو کامل نیست**. هستهٔ وردپرس، قالب و
دیتابیس اصلاً تغییر نکرده‌اند:

| بخش | تغییر کرده؟ |
|---|---|
| هستهٔ وردپرس | ❌ |
| قالب cartonpak | ❌ |
| دیتابیس | ❌ (جدول جدیدی ساخته نمی‌شود) |
| `wp-content/plugins/parsian-shop-filters` | ✅ جدید |
| `wp-content/plugins/parsian-catalog-sync` | ✅ جدید |

## روش پیشنهادی برای سرور شما — بستهٔ `deploy-plugins.zip`

این بسته دقیقاً برای همین روش کار (اکسترکت مستقیم روی سرور) ساخته شده است.

### ۱) ساخت بسته

```bash
./tools/build-plugin-zips.sh
```

خروجی در `dist/`:

| فایل | کاربرد |
|---|---|
| `deploy-plugins.zip` | **برای اکسترکت در ریشهٔ وب سرور** |
| `parsian-shop-filters.zip` | برای بارگذاری از پیشخوان |
| `parsian-catalog-sync.zip` | برای بارگذاری از پیشخوان |

### ۲) ساختار `deploy-plugins.zip`

```
wp-content/
└── plugins/
    ├── parsian-shop-filters/
    └── parsian-catalog-sync/
```

فقط همین ۲۶ فایل. هیچ فایل دیگری از سایت را لمس نمی‌کند.

### ۳) استقرار

فایل را در **ریشهٔ وب** (`public_html`) آپلود و همان‌جا اکسترکت کنید:

```bash
# با SSH
cd ~/public_html
unzip -o deploy-plugins.zip
rm deploy-plugins.zip
```

یا با **File Manager** سی‌پنل: آپلود در `public_html` ← راست‌کلیک ← Extract.

چون مسیرها از `wp-content/plugins/` شروع می‌شوند، پوشه‌ها دقیقاً سر جای خودشان
می‌نشینند.

### ۴) فعال‌سازی

پیشخوان ← **افزونه‌ها** ← هر دو افزونه را فعال کنید.

### ۵) بررسی مجوز فایل‌ها

اگر بعد از اکسترکت خطای دسترسی دیدید:

```bash
cd ~/public_html/wp-content/plugins
chown -R $USER:$USER parsian-shop-filters parsian-catalog-sync
find parsian-shop-filters parsian-catalog-sync -type d -exec chmod 755 {} \;
find parsian-shop-filters parsian-catalog-sync -type f -exec chmod 644 {} \;
```

## روش جایگزین — بارگذاری از پیشخوان (بدون SSH)

اگر به SSH یا File Manager دسترسی ندارید:

پیشخوان ← **افزونه‌ها ← افزودن ← بارگذاری افزونه** ← فایل
`parsian-shop-filters.zip` را انتخاب و نصب کنید. همین کار را برای
`parsian-catalog-sync.zip` تکرار کنید و هر دو را فعال کنید.

برای به‌روزرسانی‌های بعدی هم همین فایل را دوباره بارگذاری کنید؛ وردپرس می‌پرسد که
نسخهٔ موجود را جایگزین کند — تأیید کنید.

## `wordpress.zip` کِی به‌درد می‌خورد؟

آرشیو کامل برای این حالت‌هاست، نه برای به‌روزرسانی سایت در حال کار:

- **نصب روی هاست تازه** یا انتقال به سرور جدید
- **ساخت محیط لوکال** برای توسعه و آزمایش
- **بازیابی** پس از خرابی

`wp-config.php` داخل آرشیو برای همین آماده است: وقتی متغیرهای محیطی داکر وجود
نداشته باشند، به مقادیر هاست برمی‌گردد (`DB_HOST` روی `localhost` و نام و کاربر
دیتابیس سایت). یعنی روی هاست معمولی بدون تغییر کار می‌کند.

برای نصب تازه، دیتابیس را هم جداگانه لازم دارید (`exported-beta.sql` روی سیستم
خودتان؛ در گیت نیست).

## استقرار روی محیط لوکال (داکر)

```powershell
git pull origin claude/brave-archimedes-itzi9s

Copy-Item -Recurse -Force plugins\parsian-shop-filters wordpress\wp-content\plugins\
Copy-Item -Recurse -Force plugins\parsian-catalog-sync wordpress\wp-content\plugins\

docker compose up -d db redis wordpress
docker compose run --rm wpcli wp plugin activate parsian-shop-filters parsian-catalog-sync
```

چون `./wordpress` به‌صورت bind mount به کانتینر وصل است، فایل‌ها بلافاصله در
دسترس‌اند.

## بعد از فعال‌سازی: تنظیمات اولیه

### الف) فیلترهای فروشگاه
پیشخوان ← **محصولات ← فیلترهای فروشگاه**

پیش‌فرض‌ها معقول‌اند. برای اینکه فیلتر ویژگی‌ها معنا پیدا کند باید ویژگی‌های سراسری
تعریف شده باشند (محصولات ← ویژگی‌ها): سایز، تعداد لایه، نوع چاپ. اگر هنوز
نساخته‌اید، افزونهٔ همگام‌سازی می‌تواند از ستون‌های «ویژگی: …» فایل اکسل خودش بسازد.

### ب) همگام‌سازی با اکسل
پیشخوان ← **محصولات ← همگام‌سازی با اکسل**

**قبل از هر چیز واحد قیمت را بررسی کنید.** صفحه می‌نویسد قیمت‌ها در چه واحدی ذخیره
می‌شوند و فایل شما در چه واحدی خوانده می‌شود. اگر اشتباه باشد همهٔ قیمت‌ها ۱۰ برابر
یا یک‌دهم می‌شوند.

بعد فایل `docs/قالب-محصولات.xlsx` را با داده‌های واقعی پر کنید، بارگذاری کنید و
**حتماً اول پیش‌نمایش را بخوانید** — تا دکمهٔ «اعمال» را نزنید هیچ‌چیز تغییر نمی‌کند.

## ترتیب پیشنهادی برای اولین بار

```
۱) اول روی لوکال نصب و امتحان کنید
۲) با فایل اکسل واقعی یک «پیش‌نمایش» بگیرید و جدول تغییرات را بخوانید
۳) روی لوکال «اعمال» کنید و نتیجه را در فروشگاه ببینید
۴) از دیتابیس سایت آنلاین بکاپ بگیرید
۵) تازه بعد روی parsiancarton.com مستقر کنید
```

دلیل مرحلهٔ ۴: افزونهٔ همگام‌سازی قیمت و موجودی محصولات واقعی را تغییر می‌دهد.
پیش‌نمایش جلوی اشتباه را می‌گیرد، ولی بکاپ جای خودش را دارد.

بکاپ دیتابیس (با SSH، یا از phpMyAdmin هاست ← Export):

```bash
mysqldump -u USER -p parsiancartoncom_db > backup-$(date +%F).sql
```

## برگشت به عقب

| مشکل | راه‌حل |
|---|---|
| ظاهر فروشگاه به هم ریخت | افزونهٔ «فیلتر و جستجو» را غیرفعال کنید — فروشگاه به حالت قبل برمی‌گردد |
| همگام‌سازی نتیجهٔ اشتباه داد | محصولات «پیش‌نویس‌شده» را از پیشخوان برگردانید؛ برای قیمت‌ها فایل اکسل را درست کنید و دوباره اجرا کنید |

| می‌خواهم کاملاً پاک شود | افزونه‌ها را غیرفعال و حذف کنید؛ هیچ جدولی در دیتابیس نساخته‌اند |

غیرفعال کردن هر دو افزونه، سایت را دقیقاً به وضعیت قبل برمی‌گرداند.

## دو نکتهٔ امنیتی (بی‌ربط به این تغییرات، ولی دیدنی)

### ۱) فایل `dbg.php` در ریشهٔ وب

یک اسکریپت اشکال‌زدایی باقی‌مانده از عیب‌یابی ابعاد تصاویر SVG است. بدخواه نیست و
چون وردپرس را بارگذاری نمی‌کند عملاً کار نمی‌کند، ولی روی سایت زنده جایی ندارد:

```bash
rm ~/public_html/dbg.php
```

### ۲) کلیدهای امنیتی در `wp-config.php`

هشت کلید وردپرس (`AUTH_KEY` … `NONCE_SALT`) داخل فایل نوشته شده‌اند و همراه آرشیو
در گیت هستند. این از قبل هم همین‌طور بوده و چیز تازه‌ای نیست، ولی اگر مخزن را عمومی
می‌کنید بهتر است عوضشان کنید — با تغییرشان همهٔ نشست‌های ورود باطل می‌شوند (که
دقیقاً هدف است):

<https://api.wordpress.org/secret-key/1.1/salt/>

## چرا zip و نه rar؟

- ویندوز، مک، لینوکس و سی‌پنل همگی zip را بومی باز می‌کنند؛ rar به نرم‌افزار
  جداگانه نیاز دارد — روی سرور معمولاً `unrar` نصب نیست ولی `unzip` هست
- وردپرس خودش با zip کار می‌کند (بارگذاری افزونه و قالب)
- ابزارهای متن‌باز مثل `unar` بعضی بلوک‌های فشرده‌سازی RAR5 را پشتیبانی نمی‌کنند و
  هنگام باز کردن، بخشی از فایل‌ها را **بی‌سروصدا خالی** تحویل می‌دهند — دقیقاً همان
  اتفاقی که موقع ساخت این نسخه افتاد و تا وقتی فایل‌ها را با مانیفست آرشیو مقایسه
  نکردیم معلوم نشد

### حجم آرشیو

`wordpress.zip` حدود ۵۶ مگابایت است و گیت‌هاب برای فایل‌های بالای ۵۰ مگابایت هشدار
می‌دهد (سقف مسدودسازی ۱۰۰ مگابایت است، پس مشکلی پیش نمی‌آید). اگر بعدها خواستید
مخزن سبک شود، گزینهٔ درست این است که آرشیو از گیت خارج شود و در Releases نگهداری
شود — چون هر نسخهٔ تازه‌اش یک کپی کامل دیگر به تاریخچهٔ گیت اضافه می‌کند.
