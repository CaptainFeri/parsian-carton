# نصب و استقرار نسخهٔ جدید

## اول از همه: پوشهٔ `wordpress/` حذف نشده است

پوشهٔ `wordpress/` **هیچ‌وقت داخل گیت نبوده**. کامیت اولیهٔ مخزن فقط سه فایل داشت:

```
README.md
docker-compose.yml
wordpress.rar
```

آن پوشه روی کامپیوتر خودتان از باز کردن همان آرشیو ساخته شده بود (همان‌طور که README
توضیح داده). چون در گیت نبوده، `git pull` هم آن را پاک نمی‌کند — پوشهٔ `wordpress/`
شما سر جایش است.

از این نسخه، آرشیو به‌صورت **`wordpress.zip`** نگهداری می‌شود (به‌جای `wordpress.rar`).
محتوا مو‌به‌مو همان است: هر ۱۰٬۷۴۹ فایل با همان نام و همان اندازه، به‌علاوهٔ دو
افزونهٔ جدید که از قبل در `wp-content/plugins/` قرار گرفته‌اند.

## چه چیزی باید مستقر شود؟

فقط **دو پوشهٔ افزونه**. هستهٔ وردپرس، قالب `cartonpak` و دیتابیس دست‌نخورده‌اند:

| بخش | تغییر کرده؟ |
|---|---|
| هستهٔ وردپرس | ❌ |
| قالب cartonpak | ❌ |
| دیتابیس | ❌ (جدول جدیدی ساخته نمی‌شود) |
| `wp-content/plugins/parsian-shop-filters` | ✅ جدید |
| `wp-content/plugins/parsian-catalog-sync` | ✅ جدید |

یعنی نه نیازی به ایمپورت دوبارهٔ دیتابیس است، نه بازسازی آرشیو.

## روش ۱ — لوکال (داکر)

```powershell
# ۱) گرفتن نسخهٔ جدید
git pull origin claude/brave-archimedes-itzi9s

# ۲) کپی دو افزونه داخل نصب وردپرس خودتان
Copy-Item -Recurse -Force plugins\parsian-shop-filters wordpress\wp-content\plugins\
Copy-Item -Recurse -Force plugins\parsian-catalog-sync wordpress\wp-content\plugins\

# ۳) بالا آوردن سرویس‌ها (اگر بالا نیستند)
docker compose up -d db redis wordpress
```

چون `./wordpress` به‌صورت bind mount به کانتینر وصل است، فایل‌ها بلافاصله در دسترس‌اند.

فعال‌سازی از پیشخوان (`http://localhost:8080/wp-admin` ← افزونه‌ها) یا با wp-cli:

```powershell
docker compose run --rm wpcli wp plugin activate parsian-shop-filters parsian-catalog-sync
```

## روش ۲ — سایت آنلاین، بارگذاری zip از پیشخوان (ساده‌ترین)

۱. فایل‌های zip را بسازید:

```bash
./tools/build-plugin-zips.sh
```

خروجی در `dist/` قرار می‌گیرد:
`parsian-shop-filters.zip` و `parsian-catalog-sync.zip`

۲. در `parsiancarton.com/wp-admin` بروید به:
**افزونه‌ها ← افزودن ← بارگذاری افزونه** ← فایل zip را انتخاب و نصب کنید.

۳. همین کار را برای zip دوم تکرار کنید و هر دو را **فعال** کنید.

> برای به‌روزرسانی بعدی، همین zip را دوباره بارگذاری کنید؛ وردپرس می‌پرسد که نسخهٔ
> موجود را جایگزین کند — تأیید کنید.

## روش ۳ — سایت آنلاین، FTP یا File Manager

دو پوشهٔ زیر را مستقیم آپلود کنید:

```
plugins/parsian-shop-filters  ──▶  public_html/wp-content/plugins/parsian-shop-filters
plugins/parsian-catalog-sync  ──▶  public_html/wp-content/plugins/parsian-catalog-sync
```

سپس پیشخوان ← افزونه‌ها ← هر دو را فعال کنید.

⚠️ حتماً **کل پوشه** را آپلود کنید، نه فقط فایل‌های داخلش؛ وردپرس افزونه را از روی
پوشه‌اش می‌شناسد.

## بعد از فعال‌سازی: تنظیمات اولیه

### الف) فیلترهای فروشگاه
پیشخوان ← **محصولات ← فیلترهای فروشگاه**

پیش‌فرض‌ها معقول‌اند. برای اینکه فیلتر ویژگی‌ها معنا پیدا کند، باید ویژگی‌های
سراسری تعریف شده باشند (محصولات ← ویژگی‌ها): سایز، تعداد لایه، نوع چاپ.
اگر هنوز نساخته‌اید، افزونهٔ همگام‌سازی می‌تواند از ستون‌های «ویژگی: …» فایل اکسل
خودش بسازد.

### ب) همگام‌سازی با اکسل
پیشخوان ← **محصولات ← همگام‌سازی با اکسل**

**قبل از هر چیز واحد قیمت را بررسی کنید.** صفحه می‌نویسد قیمت‌ها در چه واحدی ذخیره
می‌شوند و فایل شما در چه واحدی خوانده می‌شود. اگر اشتباه باشد، همهٔ قیمت‌ها ۱۰ برابر
یا یک‌دهم می‌شوند.

بعد فایل `docs/قالب-محصولات.xlsx` را با داده‌های واقعی پر کنید، بارگذاری کنید و
**حتماً اول پیش‌نمایش را بخوانید** — تا دکمهٔ «اعمال» را نزنید هیچ‌چیز تغییر نمی‌کند.

## ترتیب پیشنهادی برای اولین بار

```
۱) اول روی لوکال (داکر) نصب و امتحان کنید
۲) با فایل اکسل واقعی یک «پیش‌نمایش» بگیرید و جدول تغییرات را بخوانید
۳) روی لوکال «اعمال» کنید و نتیجه را در فروشگاه ببینید
۴) از دیتابیس سایت آنلاین بکاپ بگیرید
۵) تازه بعد روی parsiancarton.com نصب کنید
```

دلیل مرحلهٔ ۴: افزونهٔ همگام‌سازی قیمت و موجودی محصولات واقعی را تغییر می‌دهد.
پیش‌نمایش جلوی اشتباه را می‌گیرد، ولی بکاپ جای خودش را دارد.

بکاپ دیتابیس آنلاین (اگر به SSH دسترسی دارید) یا از phpMyAdmin هاست:

```bash
mysqldump -u USER -p parsiancartoncom_db > backup-$(date +%F).sql
```

## برگشت به عقب

چیزی که این نسخه اضافه کرده فقط دو افزونه است، پس برگشت ساده است:

| مشکل | راه‌حل |
|---|---|
| ظاهر فروشگاه به هم ریخت | افزونهٔ «فیلتر و جستجو» را غیرفعال کنید — فروشگاه به حالت قبل برمی‌گردد |
| همگام‌سازی نتیجهٔ اشتباه داد | محصولات «پیش‌نویس‌شده» را از پیشخوان برگردانید؛ برای قیمت‌ها، فایل اکسل را درست کنید و دوباره اجرا کنید |
| قیمت‌ها ۱۰ برابر شدند | واحد قیمت در تنظیمات اشتباه بوده: اصلاحش کنید و همان فایل را دوباره اعمال کنید |
| می‌خواهم کاملاً پاک شود | افزونه‌ها را غیرفعال و حذف کنید؛ هیچ جدولی در دیتابیس نساخته‌اند |

غیرفعال کردن هر دو افزونه، سایت را دقیقاً به وضعیت قبل از این تغییرات برمی‌گرداند.

## دربارهٔ آرشیو `wordpress.zip`

آرشیو پروژه از این نسخه **zip** است، نه rar. دلیلش:

- ویندوز، مک، لینوکس و هاست‌های اشتراکی (cPanel) همگی zip را بومی باز می‌کنند؛
  rar به نرم‌افزار جداگانه نیاز دارد
- وردپرس خودش با zip کار می‌کند (بارگذاری افزونه و قالب)
- ابزارهای متن‌باز مثل `unar` و `7-Zip` بعضی بلوک‌های فشرده‌سازی RAR5 را پشتیبانی
  نمی‌کنند و هنگام باز کردن، بخشی از فایل‌ها را **بی‌سروصدا خالی** تحویل می‌دهند —
  دقیقاً همان اتفاقی که موقع ساخت این نسخه افتاد و تا وقتی فایل‌ها را با مانیفست
  آرشیو مقایسه نکردیم معلوم نشد

### باز کردن

```powershell
# ویندوز
Expand-Archive wordpress.zip -DestinationPath .

# لینوکس / مک
unzip wordpress.zip
```

خروجی یک پوشهٔ `wordpress/` است — همان چیزی که `docker-compose.yml` انتظار دارد.

### دو نکته

**۱) `wp-config.php` داخل آرشیو است.** این فایل برای داکر تنظیم شده (مقادیر از
متغیرهای محیطی `docker-compose.yml` خوانده می‌شوند)، ولی هشت کلید امنیتی وردپرس
(`AUTH_KEY`, `SECURE_AUTH_KEY`, … `NONCE_SALT`) داخلش نوشته شده‌اند. این از قبل هم در
مخزن بود و چیز تازه‌ای نیست، ولی اگر مخزن را عمومی می‌کنید بهتر است این کلیدها را
عوض کنید؛ با تغییرشان همهٔ نشست‌های ورود باطل می‌شوند (که دقیقاً همان هدف است):

<https://api.wordpress.org/secret-key/1.1/salt/>

**۲) حجم آرشیو ۵۶ مگابایت است.** گیت‌هاب برای فایل‌های بالای ۵۰ مگابایت هشدار
می‌دهد (سقف مسدودسازی ۱۰۰ مگابایت است، پس مشکلی پیش نمی‌آید). اگر بعدها خواستید
مخزن سبک شود، گزینهٔ درست این است که آرشیو از گیت خارج شود و در Releases یا فضای
دیگری نگهداری شود — چون هر نسخهٔ تازهٔ آن، یک نسخهٔ کامل دیگر به تاریخچهٔ گیت
اضافه می‌کند.
