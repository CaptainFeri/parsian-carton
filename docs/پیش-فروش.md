# مدیریت پیش‌فروش

افزونهٔ `plugins/parsian-preorder` پیش‌فروش را از یک «فرم تماس بگیرید» به یک
**کارتابل فروش** تبدیل می‌کند: هر درخواست شماره دارد، وضعیت دارد، مسئول پیگیری
دارد، تاریخ پیگیری بعدی دارد، تاریخچهٔ کامل دارد و در پایان با یک کلیک به سفارش
ووکامرس تبدیل می‌شود.

## نصب

۱. پوشهٔ `plugins/parsian-preorder` را در `wp-content/plugins/` کپی کنید
   (یا `dist/parsian-preorder.zip` را از پیشخوان بارگذاری کنید).
۲. پیشخوان ← افزونه‌ها ← «پارسیان کارتن — مدیریت پیش‌فروش» ← فعال‌سازی.
۳. منوی تازهٔ **پیش‌فروش** در ستون کنار پیشخوان ظاهر می‌شود.

> نسخهٔ قدیمی افزونه (که فقط فرم و فهرست ساده داشت) هنگام فعال‌سازی **خودکار
> ارتقا می‌شود**: درخواست‌های ثبت‌شده، محصولات پیش‌فروش و تنظیمات پیامک سر جایشان
> می‌مانند و وضعیت‌های قدیمی (جدید / تماس گرفته شد / تبدیل به سفارش / لغو شده) به
> خط لولهٔ تازه منتقل می‌شوند.

## دسترسی

دسترسی `manage_preorders` هنگام فعال‌سازی به نقش‌های **مدیر** و **مدیر فروشگاه**
داده می‌شود. اگر می‌خواهید یک «کارشناس فروش» فقط کارتابل را ببیند، همین دسترسی را
به نقشش بدهید:

```php
get_role( 'sales_agent' )->add_cap( 'manage_preorders' );
```

## بخش اول: تنظیم پیش‌فروش روی محصول

صفحهٔ ویرایش محصول ← زبانهٔ **پیش‌فروش**:

| تنظیم | کارش |
|---|---|
| پیش‌فروش فعال است | دکمهٔ «افزودن به سبد» با فرم درخواست جایگزین می‌شود |
| زمان آماده‌سازی (روز کاری) | به مشتری نمایش داده می‌شود و در سفارش ثبت می‌شود |
| تاریخ عرضه | شمسی یا میلادی؛ روی صفحهٔ محصول با «چند روز مانده» نشان داده می‌شود |
| پایان خودکار | با رسیدن تاریخ عرضه، پیش‌فروش خودبه‌خود خاموش و محصول عادی می‌شود |
| حداقل تیراژ | کمتر از این تعداد، درخواست ثبت نمی‌شود |
| ظرفیت پیش‌فروش | سقف بسته‌های این دوره؛ با پر شدن، فرم بسته می‌شود |
| قیمت ویژهٔ پیش‌فروش | مبنای برآورد مبلغ درخواست (خالی = قیمت عادی محصول) |
| پیش‌پرداخت (درصد) | در فرم به مشتری اعلام می‌شود |
| یادداشت پیش‌فروش | متن کوتاهی که بالای فرم دیده می‌شود (شرایط چاپ، حداقل سفارش…) |

**ظرفیت چطور حساب می‌شود؟** مجموع بسته‌های همهٔ درخواست‌های *باز* به‌اضافهٔ
درخواست‌های *تبدیل‌شده به سفارش*. درخواست لغوشده ظرفیت را آزاد می‌کند.

### تنظیم گروهی با فایل اکسل

اگر افزونهٔ «همگام‌سازی کاتالوگ با اکسل» هم فعال باشد، شش ستون پیش‌فروش خودکار به
فایل کاتالوگ اضافه می‌شوند: پیش‌فروش، زمان آماده‌سازی، تاریخ عرضه، ظرفیت، حداقل
تیراژ و پیش‌پرداخت. یعنی راه‌اندازی یک دورهٔ پیش‌فروش برای ۵۰ محصول یک ستون در
اکسل است، نه ۵۰ بار باز کردن ویرایشگر محصول.

## بخش دوم: آنچه مشتری می‌بیند

- روی کارت محصول در فروشگاه: نشان «پیش‌فروش» (متن و رنگش در تنظیمات).
- بالای صفحهٔ محصول: تاریخ عرضه، زمان آماده‌سازی و ظرفیت باقی‌مانده.
- به‌جای دکمهٔ خرید: فرم درخواست با تعداد، موبایل، نام، شرکت، شهر و توضیحات
  (هر کدام را می‌توانید در تنظیمات خاموش کنید) و برآورد زندهٔ مبلغ.
- محصول پیش‌فروش از راه نشانی مستقیم `?add-to-cart=` هم وارد سبد نمی‌شود.
- زبانهٔ **پیش‌فروش‌های من** در حساب کاربری، وضعیت درخواست‌ها را به مشتری نشان می‌دهد.

## بخش سوم: کارتابل

### داشبورد

`پیش‌فروش ← داشبورد` — یک نگاه به کل وضعیت:

- درخواست‌های باز، امروز، هفتهٔ گذشته
- **پیگیری عقب‌افتاده** (مهم‌ترین عدد صفحه)
- ارزش درخواست‌های باز و ارزش سفارش‌شده‌ها
- نرخ تبدیل به سفارش
- خط لولهٔ وضعیت‌ها، نمودار دو هفتهٔ اخیر، پرتقاضاترین محصولات

### خط لولهٔ وضعیت

```
جدید ──▶ در تماس ──▶ پیش‌فاکتور ──▶ تأیید مشتری ──▶ در حال تولید ──▶ آمادهٔ ارسال ──▶ تبدیل به سفارش
                                                                                    └──▶ لغو شده
```

شش وضعیت اول «باز» شمرده می‌شوند و در آمار کارهای روی میز می‌آیند. دو وضعیت آخر
پرونده را می‌بندند.

وضعیت هر درخواست **وضعیت خود نوشته** است، نه یک فیلد اضافه؛ به همین دلیل شمارش هر
مرحله یک پرس‌وجوی ساده است و کارتابل با چند هزار درخواست هم کند نمی‌شود.

### فهرست درخواست‌ها

`پیش‌فروش ← درخواست‌ها`:

- فیلتر بر اساس وضعیت (با شمارش)، محصول، مسئول پیگیری و «فقط عقب‌افتاده‌ها»
- جستجو بر اساس شمارهٔ درخواست، شمارهٔ موبایل، نام، شرکت یا شهر
- عملیات گروهی: تغییر وضعیت، واگذاری به خودم، خروجی CSV از انتخاب‌شده‌ها، حذف
- علامت قرمز `!` روی درخواست‌هایی که پیگیری‌شان از تاریخ گذشته است

### صفحهٔ یک درخواست

سمت راست: اطلاعات مشتری و محصول، و **تاریخچهٔ کامل** — هر تغییر وضعیت، هر پیامک
(موفق یا ناموفق، با متن خطا)، هر واگذاری و هر یادداشت دستی، با نام کاربر و زمان.
وقتی مشتری می‌گوید «پیامکی نیامد»، پاسخ در همین صفحه است.

سمت چپ، کارهای کارشناس:

- تغییر وضعیت (با یادداشت اختیاری برای همان تغییر)
- واگذاری به یک کارشناس
- تاریخ پیگیری بعدی (شمسی)
- اولویت
- **تعداد و قیمت واحد توافق‌شده** — همین دو عدد در سفارش نوشته می‌شوند
- دکمهٔ **ساخت سفارش ووکامرس**

### تبدیل به سفارش

یک کلیک، یک سفارش «در انتظار پرداخت» با محصول، تعداد و قیمت توافق‌شده، مشخصات
مشتری پرشده، و یک یادداشت سفارش که تاریخ عرضه، زمان آماده‌سازی و توضیحات مشتری را
نگه می‌دارد. درخواست خودکار به وضعیت «تبدیل به سفارش» می‌رود و پیوند دوطرفه میان
درخواست و سفارش ساخته می‌شود (ستون «پیش‌فروش» در فهرست سفارش‌ها).

### محصولات پیش‌فروش

`پیش‌فروش ← محصولات` — یک جدول از همهٔ دوره‌های باز: تاریخ عرضه، ظرفیت، رزروشده
(با نوار پیشرفت)، پیش‌پرداخت و وضعیت (باز / ظرفیت تکمیل / پایان‌یافته).

### خروجی CSV

دکمهٔ «خروجی CSV» بالای فهرست، همان فیلترهای جاری را برون‌ریزی می‌کند: ۱۸ ستون
شامل وضعیت، مشتری، تعداد، ارزش، مسئول پیگیری و شمارهٔ سفارش. فایل با BOM و پایان
خط ویندوزی ساخته می‌شود تا اکسل فارسی را درست باز کند، و سلول‌های فرمول‌نما خنثی
می‌شوند.

## بخش چهارم: اطلاع‌رسانی

`پیش‌فروش ← تنظیمات`:

- **پیامک (کاوه‌نگار):** قالب پیامک تأیید برای مشتری، قالب اطلاع‌رسانی به پشتیبانی،
  و یک قالب دلخواه برای **هر وضعیت** — مثلاً با رسیدن درخواست به «آمادهٔ ارسال»
  خودکار به مشتری خبر برود. خالی گذاشتن هر کدام یعنی پیامکی فرستاده نشود.
  کلید API اگر اینجا خالی باشد از افزونهٔ «ورود با پیامک» برداشته می‌شود.
- **ایمیل:** با هر درخواست تازه، خلاصهٔ درخواست به یک یا چند نشانی می‌رود.

بدون کلید API، درخواست‌ها بدون مشکل ثبت می‌شوند و فقط پیامکی فرستاده نمی‌شود —
و همین در تاریخچهٔ درخواست ثبت می‌شود.

## گردش کار

`پیش‌فروش ← تنظیمات ← گردش کار`:

| تنظیم | کارش |
|---|---|
| وضعیت درخواست تازه | معمولاً «جدید» |
| مسئول پیش‌فرض | هر درخواست تازه خودکار به این کارشناس واگذار می‌شود |
| پیگیری بعدی، چند روز بعد | تاریخ پیگیری درخواست تازه همین‌قدر جلوتر گذاشته می‌شود |
| مهلت پیش‌فرض پیگیری | درخواست بازِ بی‌تاریخ که از این چند روز گذشته باشد «عقب‌افتاده» می‌شود |
| پنجرهٔ ضد تکرار | ثبت دوبارهٔ همان محصول با همان شماره در این چند دقیقه رد می‌شود |

## توسعه

```php
// افزودن یک مرحله به خط لوله
add_filter( 'ppo_statuses', function ( $statuses ) {
	$statuses['ppo-shipped'] = array(
		'label'       => 'ارسال شد',
		'short'       => 'ارسال',
		'color'       => '#0f766e',
		'open'        => false,
		'description' => 'کالا تحویل باربری شده است.',
	);
	return $statuses;
} );

// واکنش به ثبت درخواست تازه
add_action( 'ppo_request_created', function ( $request ) {
	error_log( 'درخواست تازه: ' . $request->get_id() );
} );

// واکنش به تغییر وضعیت
add_action( 'ppo_request_status_changed', function ( $request, $status, $previous ) {
	// …
}, 10, 3 );
```

> کلید وضعیت نباید بلندتر از ۲۰ نویسه باشد (سقف ستون `post_status` در وردپرس)؛
> آزمون‌ها همین را هم بررسی می‌کنند.

## آزمون‌ها

```bash
./tests/run.sh
```

`tests/test-preorder.php` بدون نیاز به وردپرس این‌ها را می‌سنجد: یکدست‌سازی شمارهٔ
موبایل، تبدیل تاریخ شمسی (رفت‌وبرگشت کامل ۱۸ سال)، خط لولهٔ وضعیت، پاک‌سازی
تنظیمات، نوشتن CSV، و اینکه ستون‌های پیش‌فروش واقعاً در فایل کاتالوگ شناخته
می‌شوند.
