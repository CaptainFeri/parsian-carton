# فایل اکسل به‌عنوان مرجع محصولات

افزونهٔ `plugins/parsian-catalog-sync` اجازه می‌دهد یک فایل اکسل، **منبع حقیقت**
محصولات باشد: قیمت، موجودی، دسته‌بندی، تصویر و ویژگی‌ها را در فایل اصلاح می‌کنید
و فروشگاه با آن هم‌گام می‌شود.

## نصب

۱. پوشهٔ `plugins/parsian-catalog-sync` را در `wp-content/plugins/` کپی کنید.
۲. پیشخوان ← افزونه‌ها ← «پارسیان کارتن — همگام‌سازی کاتالوگ با اکسل» ← فعال‌سازی.
۳. پیشخوان ← محصولات ← **همگام‌سازی با اکسل**.

## جریان کار

```
فایل اکسل  ──▶  «نمایش پیش‌نمایش»  ──▶  جدول تغییرات  ──▶  «اعمال»  ──▶  فروشگاه
                                            │
                                   اینجا هنوز هیچ‌چیز
                                    تغییر نکرده است
```

همگام‌سازی **ایدم‌پوتنت** است: اجرای دوبارهٔ همان فایل، هیچ تغییری ایجاد نمی‌کند و
همهٔ سطرها «بدون تغییر» گزارش می‌شوند.

## روش پیشنهادی: خروجی خود ووکامرس را ویرایش کنید

لازم نیست فایل را از صفر بسازید. ووکامرس خودش یک خروجی کامل می‌دهد که این افزونه
آن را **بدون هیچ دست‌کاری** می‌خواند:

```
پیشخوان ← محصولات ← همهٔ محصولات ← «برون‌ریزی»
   ↓
فایل CSV را در اکسل باز کنید و فقط ستون قیمت/موجودی را عوض کنید
   ↓
پیشخوان ← محصولات ← همگام‌سازی با اکسل ← بارگذاری ← پیش‌نمایش ← اعمال
```

این چرخه آزموده شده است: **اگر فایل را برون‌ریزی کنید و بدون هیچ ویرایشی دوباره وارد
کنید، هیچ محصولی تغییر نمی‌کند.** اگر یک قیمت را عوض کنید، دقیقاً همان یک سطر و همان
یک فیلد در پیش‌نمایش ظاهر می‌شود.

### ستون‌های خروجی ووکامرس که خوانده می‌شوند

| ستون ووکامرس | معادل |
|---|---|
| شناسه محصول | کلید یکتا (SKU) |
| نوع | نوع محصول — رفتار همگام‌سازی را تعیین می‌کند |
| نام، توضیحات، توضیح کوتاه | همان |
| قیمت عادی، قیمت فروش ویژه | قیمت و قیمت حراج |
| انبار، در انبار؟ | موجودی و وضعیت آن |
| دسته‌بندی‌ها، برچسب‌ها | همان |
| تصاویر | اولی تصویر شاخص، بقیه گالری |
| منتشر شده (۱/۰/‎-۱) | منتشر / پیش‌نویس / خصوصی |
| آیا ویژه است؟، موقعیت | محصول ویژه و ترتیب |
| وزن (پوند)، درازا/پهنا/بلندا (اینچ) | ابعاد — واحدِ داخل پرانتز نادیده گرفته می‌شود |
| مادر | والد واریاسیون |

ستون‌هایی مثل کلاس مالیاتی، دانلودها، Cross-Sells و برندها **خوانده نمی‌شوند و
دست‌نخورده می‌مانند** — افزونه فقط چیزی را عوض می‌کند که می‌شناسد.

### واحد قیمت در خروجی ووکامرس

قالب این سایت قیمت‌ها را ریالی ذخیره و تومانی نمایش می‌دهد. برون‌ریز ووکامرس قیمت را
با `get_regular_price()` می‌خواند که در کانتکست `view` اجرا می‌شود، یعنی **فیلتر قالب
روی آن اعمال شده و عدد داخل فایل تومان است**.

بنابراین تنظیم پیش‌فرض («واحد قیمت در فایل: تومان») برای این خروجی درست است و
رفت‌وبرگشت، عدد را تغییر نمی‌دهد.

## محصولات متغیر و واریاسیون‌ها

فروشگاه شما محصول متغیر دارد (مثلاً «سینی تک پرس» با دو حالت «یک رو» و «VIP دو رو»).
افزونه با هر نوع، متفاوت رفتار می‌کند:

| نوع | چه چیزی اعمال می‌شود | چه چیزی نه |
|---|---|---|
| **ساده** | همه‌چیز | — |
| **متغیر** (والد) | نام، توضیحات، دسته‌بندی، تصویر، وضعیت | **قیمت و موجودی** — این‌ها از واریاسیون‌ها می‌آیند |
| **واریاسیون** | **قیمت، موجودی**، وزن، ابعاد، تصویر | دسته‌بندی، برچسب، نام — واریاسیون این‌ها را از والد می‌گیرد |

قیمت واقعی فروشگاه شما در واریاسیون‌هاست، و دقیقاً همان‌جا به‌روز می‌شود.

> ⚠️ افزونه **واریاسیون یا محصول متغیر تازه نمی‌سازد.** ساخت واریاسیون به والد و
> نگاشت صفت‌ها وابسته است و ساختن نادرستش محصول را خراب می‌کند. محصول متغیر تازه را
> اول در پیشخوان بسازید؛ از آن به بعد قیمت و موجودی‌اش از فایل به‌روز می‌شود.

## صفت‌ها پیش‌فرض خاموش‌اند

ستون‌های صفت (چه «ویژگی: سایز» در قالب خودمان، چه «نام ۱ صفت» در خروجی ووکامرس)
خوانده می‌شوند ولی **به‌صورت پیش‌فرض اعمال نمی‌شوند**.

دلیل: صفت‌های یک محصول متغیر تعیین می‌کنند چه واریاسیون‌هایی وجود دارد. بازنویسی‌شان
از روی فایل می‌تواند پیوند واریاسیون‌ها با والدشان را بشکند. اگر در تنظیمات روشنش
کنید، حتی آن وقت هم فقط روی **محصولات ساده** اعمال می‌شود.

## قالب فایل

فایل نمونه: [`docs/قالب-محصولات.xlsx`](./قالب-محصولات.xlsx) — سطر اول سرستون‌هاست.

| ستون | اجباری | توضیح |
|---|---|---|
| **کد محصول** | ✅ | کلید یکتا. با همین کد محصول پیدا و به‌روز می‌شود |
| نام محصول | فقط برای محصول جدید | عنوان در فروشگاه |
| دسته بندی | — | چند دسته با کاما؛ زیردسته با `>` مثل `کارتن اسباب‌کشی>۵ لایه` |
| قیمت | — | قیمت اصلی (واحدش در تنظیمات تعیین می‌شود) |
| قیمت حراج | — | خالی یعنی بدون حراج |
| موجودی | — | تعداد؛ صفر یعنی ناموجود |
| وضعیت موجودی | — | `موجود` / `ناموجود` / `پیش‌سفارش` |
| تصویر | — | نام فایل در کتابخانهٔ رسانه، یا آدرس کامل تصویر |
| گالری | — | چند تصویر با کاما |
| توضیح کوتاه / توضیحات | — | متن صفحهٔ محصول |
| ویژگی: … | — | هر ستونی که با `ویژگی:` شروع شود به ویژگی محصول تبدیل می‌شود |
| وزن، طول، عرض، ارتفاع | — | برای محاسبهٔ حمل |
| وضعیت | — | `منتشر` / `پیش‌نویس` |
| برچسب‌ها، ترتیب، ویژه | — | اختیاری |

### قانون کلیدی: سلول خالی یعنی «دست نزن»

سلول خالی **مقدار فعلی را پاک نمی‌کند**، فقط از تغییر آن صرف‌نظر می‌شود. برای خالی
کردن یک مقدار، محصول را در پیشخوان ویرایش کنید. این کار عمدی است تا یک ستون
جاافتاده در فایل، توضیحات همهٔ محصولات را پاک نکند.

### چیزهایی که به‌نفعِ شما سخت‌گیرانه نیستند

- ارقام فارسی و عربی پذیرفته می‌شوند: `۴۵٬۰۰۰` = `45000`
- جداکنندهٔ هزارگان (`٬` `،` `,`) و واحد (`تومان`، `ریال`) نادیده گرفته می‌شود
- نیم‌فاصله در سرستون‌ها مهم نیست: «دسته‌بندی» و «دسته بندی» یکی‌اند
- «ي» و «ك» عربی خودکار به «ی» و «ک» تبدیل می‌شوند
- نام‌های جایگزین ستون‌ها هم کار می‌کنند: `SKU`، `Price`، `انبار`، `عنوان محصول`، …
- سطرهای عنوان و خالیِ بالای جدول رد می‌شوند

## واحد قیمت — مهم‌ترین تنظیم

قیمت‌ها در دیتابیس این سایت **به ریال** ذخیره شده‌اند (قالب موقع نمایش بر ۱۰ تقسیم
می‌کند). در تنظیمات افزونه مشخص می‌کنید فایل شما به **تومان** است یا **ریال**، و
افزونه خودش تبدیل را انجام می‌دهد.

پیش‌فرض: فایل به **تومان** ⟶ ضرب در ۱۰ برای ذخیره. همین مقدار در صفحهٔ تنظیمات و
بالای پیش‌نمایش نوشته می‌شود تا اشتباه نشود.

## محصولاتی که در فایل نیستند

در تنظیمات انتخاب می‌کنید:

| گزینه | رفتار |
|---|---|
| **پیش‌نویس** (پیش‌فرض) | از فروشگاه پنهان می‌شوند ولی حذف نمی‌شوند — قابل بازگرداندن |
| ناموجود | باقی می‌مانند ولی قابل سفارش نیستند |
| دست‌نخورده | هیچ کاری انجام نمی‌شود |
| زباله‌دان | به سطل زباله می‌روند |

محصولات **بدون کد محصول** هرگز تغییر نمی‌کنند، چون با فایل قابل تطبیق نیستند.

## همگام‌سازی خودکار (بدون بارگذاری دستی)

در تنظیمات، «منبع ثابت» را روی یک نشانی اینترنتی بگذارید و زمان‌بندی را تعیین کنید
(ساعتی / روزی دو بار / روزانه). مناسب‌ترین گزینه: **گوگل‌شیت**.

> 🛟 **محافظ خودکار:** در حالت زمان‌بندی‌شده پیش‌نمایشی وجود ندارد که جلوی اشتباه را
> بگیرد. اگر فایل ناقص باشد (برون‌ریزی فیلترشده، دانلود نیمه‌کاره) و بیش از ۲۰ درصد
> محصولات فروشگاه در آن نباشند، همگام‌سازی خودکار **متوقف می‌شود** و دلیلش در
> تاریخچه ثبت می‌شود — به‌جای اینکه کل فروشگاه را پیش‌نویس کند. این محافظ فقط وقتی
> فعال است که رفتار «محصولات غایب» تخریبی باشد.

## پیشنهاد: به‌جای فایل اکسل، از گوگل‌شیت استفاده کنید

کار کردن با فایل اکسل روی کامپیوتر یک ایراد عملی دارد: هر بار باید فایل را باز
کنید، ذخیره کنید، به پیشخوان بروید و بارگذاری کنید — و اگر دو نفر همزمان فایل را
عوض کنند، نسخه‌ها قاطی می‌شود.

**روش پیشنهادی:**

۱. همان فایل را در Google Sheets باز کنید (ساختار ستون‌ها عوض نمی‌شود).
۲. `File ← Share ← Publish to web` ← برگهٔ «محصولات» ← قالب **CSV** ← انتشار.
۳. نشانی به‌دست‌آمده را در «منبع ثابت» بگذارید و زمان‌بندی را روی **هر ساعت** بگذارید.

نتیجه:

- قیمت را در گوگل‌شیت عوض می‌کنید، حداکثر یک ساعت بعد در سایت اعمال می‌شود
- از موبایل هم قابل ویرایش است
- تاریخچهٔ کامل تغییرات و «چه کسی چه چیزی را عوض کرد» رایگان دارید
- چند نفر همزمان می‌توانند کار کنند
- فایل اکسل هم همچنان کار می‌کند؛ هر وقت خواستید دستی بارگذاری کنید

⚠️ نشانی منتشرشدهٔ گوگل‌شیت برای هر کسی که آن را داشته باشد قابل دیدن است. اگر
قیمت خرید یا اطلاعات محرمانه در همان برگه دارید، یک برگهٔ جدا فقط برای انتشار
بسازید و با `IMPORTRANGE`/`=` مقادیر لازم را در آن بیاورید.

### چرا افزونه‌های آمادهٔ درون‌ریزی را پیشنهاد نمی‌کنیم

- **درون‌ریز CSV خود ووکامرس**: فقط CSV می‌خواند، پیش‌نمایش تغییرات ندارد،
  زمان‌بندی خودکار ندارد و با واحد ریال/تومان این سایت کاری نمی‌کند.
- **WP All Import**: قوی است ولی نسخهٔ رایگانش برای محصولات ووکامرس کافی نیست و
  تنظیماتش برای یک کاربر غیرفنی سنگین است.

افزونهٔ حاضر همان کار را با یک قالب فارسی، پیش‌نمایش تغییرات و تبدیل خودکار واحد
قیمت انجام می‌دهد.

## گزارش و تاریخچه

هر اجرا (دستی یا خودکار) با تعداد محصولات ساخته‌شده، به‌روزشده، بدون تغییر و
ناموفق در پایین همان صفحه ثبت می‌شود؛ ۲۰ اجرای آخر نگه داشته می‌شود.

## توسعه

```php
// افزودن نام تازه برای یک ستون
add_filter( 'pcs_column_aliases', function ( $map ) {
	$map['regular_price'][] = 'قیمت مصرف‌کننده';
	return $map;
} );

// اگر واحد قیمت دیتابیس عوض شد
add_filter( 'pcs_store_price_unit', function () {
	return 'toman';
} );
```

## آزمون‌ها

```bash
./tests/run.sh
```

آزمون‌ها به وردپرس یا دیتابیس نیاز ندارند؛ خوانندهٔ اکسل، نگاشت ستون‌ها، تبدیل
واحد قیمت و ساخت نقشهٔ تغییرات را با وردپرسِ شبیه‌سازی‌شده بررسی می‌کنند.
